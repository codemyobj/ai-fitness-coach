这一版做了什么

  • 头像 + 昵称：用户卡右上「编辑」→ 弹层里用微信官方 open-type="chooseAvatar" 和 <input type="nickname">。 头像临时文件用 saveFile 落到本地用户目录（USER_DATA_PATH），重启不丢； 昵称本地存一份，有云档案时同步到 profiles（失败不阻塞）。
  • 重量单位 kg / lb：数据库永远存 kg，只在输入和展示两个边界换算。 影响的页面：我的（档案体重）、身体记录（概览 / 趋势 / 列表 / 输入框与范围提示）、数据看板（训练容量）、建档（体重输入）。
  • 清空训练数据：删云端 workout_logs / body_records / chat_messages / plans， 档案、收藏、设置保留。两道确认，单次上限 500 条（超了会提示再点一次）。
  • 「编辑身体档案」本来就有回填逻辑，这次顺手把体重输入也接上单位换算。

为什么这么设计

  • 换单位不迁移历史数据：一份数据只有一种含义（kg），不会出现「旧数据是 kg、新数据是 lb」的混乱
  • 头像存本地而不是云存储：个人展示用，省云存储空间和上传等待；换设备重选一次即可
  • 清空数据走客户端分批删除（_id 逐条 remove）， 不新增云函数、不用重新部署；每批 20 条、单集合上限 500 条，防异常数据卡死
  • lb 输入范围提示跟着单位走（44-661 lb），不会出现「提示 20-300 但你填的是磅」的错位

新增服务

  • services/units.js — 单位偏好与换算（含输入范围、格式化）
  • services/userinfo.js — 头像落盘、昵称清洗与云同步
  • services/data.js — 分批清理云端数据（带进度回调与上限保护）

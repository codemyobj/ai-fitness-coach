# 训练提醒 · 配置与部署指南

代码已全部写完（云函数 + 前端 + 设置页 + 打卡后引导），跑完测试全绿。
**但提醒默认不会发出**——还差 4 步「平台侧配置」，因为这些必须在微信公众平台和控制台上手动做，代码替代不了。

---

## 一、先理解机制：为什么只能「一次授权 = 一条提醒」

| | 说明 |
|---|---|
| 长期订阅 | 只有政务、医疗、交通等**公共服务类目**才能申请。体育/工具类小程序拿不到 |
| 一次性订阅 | 用户点一次「允许」= 服务端可以发 **1 条**。发完就要再授权 |
| 用户的感受 | 如果做成「开一次管一辈子」，用户开完第二天就收不到了，会以为是 bug |

所以产品形态定成：

```
打卡成功 → 顺带弹「明天还要提醒你吗？」→ 用户点允许（额度 +1）
        → 次日到点：查出「未打卡 + 有额度」→ 发一条 → 额度 -1
```

**当天已经打过卡就不发**，额度不会被浪费 —— 这是这个功能能被用户接受的关键。
`reminders` 集合里的 `quota` 字段就是「还剩几条能发」，设置页顶部直接显示。

## 二、4 步配置（必须按顺序）

### 第 1 步：申请订阅消息模板

1. 登录 [微信公众平台](https://mp.weixin.qq.com) → 你的小程序
2. 左侧 **功能 → 订阅消息 → 公共模板库**
3. 搜索关键词（建议依次试）：`训练提醒`、`打卡提醒`、`任务提醒`、`健身`
4. 优先选**类目匹配 + 字段最少**的模板。一个通用好用的组合是：

   | 模板字段名 | 类型 | 用途 |
   |---|---|---|
   | `thing1` | 提醒事项 | 放「今日训练提醒」 |
   | `time2` | 提醒时间 | 放「2026年10月7日 19:00」 |
   | `thing3` | 温馨提示 | 放「点开完成今天的计划吧」 |

5. 选用后，在 **我的模板** 里复制 **模板 ID**（形如 `aBcDeFgHiJkLmNoPqRsTuVwXyZ1234567890`）

> 📌 选完记得把上表三行的字段名抄下来 —— 第 3 步要用。
> 模板字段**不能随便加**：多发一个模板里没有的字段，微信会直接以「参数不准确」拒发。

### 第 2 步：部署云函数 + 配环境变量

1. 开发者工具里右键 `cloudfunctions/sendReminder` → **上传并部署：云端安装依赖**
2. 部署完成后，去 [云开发控制台](https://console.cloud.tencent.com/tcb) → 云函数 → `sendReminder` → **配置 → 环境变量**，加两条：

   | 变量名 | 值 | 说明 |
   |---|---|---|
   | `REMINDER_TEMPLATE_ID` | 第 1 步复制的模板 ID | **不配则整个函数只打日志、不发送** |
   | `MINIPROGRAM_STATE` | `developer` | 开发期用 `developer`（只推开发版）；正式上线后改成 `formal` 或删掉此项 |

3. 同一页 **触发器** 标签下应能看到 `hourlyReminder`（`0 0 * * * * *`，每小时整点）。
   这是 `config.json` 里声明的定时触发器，部署时自动创建；看不到就手动加一条「定时触发 → 每小时」。 
   > 为什么按小时跑：提醒时间由用户自己选，定时器只能固定时间触发，所以每小时扫一次、只发给「用户选的整点 == 当前整点」的人。24 次/天，免费额度内可忽略。

### 第 3 步：填模板 ID + 校对字段映射（两处）

**① 小程序侧** —— `miniprogram/services/reminder.js`：

```js
const TEMPLATE_ID = 'REPLACE_WITH_TEMPLATE_ID';   // ← 换成你的模板 ID
```

**② 云函数侧** —— `cloudfunctions/sendReminder/index.js`，按第 1 步抄下来的字段名改：

```js
const FIELD_MAP = { thing: 'thing1', time: 'time2', remark: 'thing3' };
//                    ↑ 文案内容        ↑ 模板里的真实字段名（改这里）
```

改完 **重新上传部署 sendReminder**，并且重新编译小程序。

### 第 4 步：建集合 + 设权限

云开发控制台 → 数据库 → 新建集合 `reminders` → 权限设为 **仅创建者可读写**。

> 也可以直接在「我的 → 训练提醒」页点一次开启，App 会检测到集合缺失并自动跑 `initDb` 补建。
> 但**权限**这一项 API 改不了，只能在控制台手动设。

## 三、验证链路（30 秒自检）

1. 重新编译小程序 → **我的 → 训练提醒**
2. 页面顶部如果显示 **「⚠️ 提醒模板未配置」** → 说明第 3 步①没改
3. 点 **「开启训练提醒」** → 应弹出微信订阅授权框 → 点「允许」
   - 弹不出来：基础库低于 2.8.2，或 `requestSubscribeMessage` 不在用户点击回调里
4. 页面显示 **「剩余 1 次」** → 说明授权 + 落库都通了
5. 点 **「发送测试提醒」** → 微信「服务通知」里应立刻收到
   - 报 `未配置模板 ID` → 第 2 步漏了
   - 报 `参数不准确(errCode 47003)` → 第 3 步②字段名和模板对不上
   - 报 `用户拒绝接收(errCode 43101)` → 额度已用掉，重新点「续订 1 次提醒」

> ⚠️ 测试发送同样消耗 1 次真实额度（微信侧的规则，不是我们扣的），测完记得再订一次。

## 四、定时触发怎么自测（不想等到 19:00）

云函数 `sendReminder` 直接支持手动跑：

- **不带参数**（`{}`）→ 等同定时器触发一轮批量扫描。想立刻看到效果，就把数据库里自己那条 `reminders.hour` 改成**当前小时**，再点「测试」。
- **带参数**（`{"action":"test"}`）→ 只给自己发一条，跳过时间与打卡校验。

云开发控制台 → 云函数 → `sendReminder` → **测试** → 贴入参数即可。返回值里带 `sent / failed / skipped` 统计和跳过原因，一眼能看出为什么没人收到。

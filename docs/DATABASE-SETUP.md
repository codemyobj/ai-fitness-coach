# 数据库初始化指南

> 项目：轻练打卡健身小程序 ｜ 路径 `D:\学习\前端\小程序\ai-fitness-coach`
> 适用：首次部署、新环境搭建、或页面报「加载失败」时排查

## 为什么需要初始化

微信云开发有个特性：**集合不存在时，查询会直接报错**，而不是返回空数组：

```
errCode: -502005  errMsg: database collection not exists
```

项目用到 6 个集合，任何一个是新的、还没建过，对应页面就会「加载失败」。

| 集合 | 用途 | 触发页面 |
|---|---|---|
| `users` | 用户基础信息 | 登录（自动创建） |
| `profiles` | 身体档案（目标/身高体重/频率） | 训练首页、建档 |
| `plans` | 训练计划 | 训练首页、计划页 |
| `workout_logs` | 训练打卡记录 | 跟练、打卡、看板 |
| `body_records` | 体重/体脂记录 | 身体记录 |

> **`chat_messages` 已下线**（原「AI 对话历史」，2026-10-08 随 AI 功能移除，见 [`docs/REVIEW-AI-REMOVAL.md`](./REVIEW-AI-REMOVAL.md)）。
> `initDb` 已不再初始化该集合；若你的云环境里已经建过，可在云开发控制台直接删除，不影响运行。

## 一键初始化（推荐）

项目已内置 `initDb` 云函数，幂等可重复执行：

1. 开发者工具左侧 → `cloudfunctions` → 右键 `initDb` → **上传并部署：云端安装依赖**
2. 云开发控制台 → **云函数** → `initDb` → **测试** → 入参留空 `{}` → 执行
3. 看返回结果：

```json
{
  "code": 0,
  "message": "全部集合已就绪",
  "results": [
    { "name": "users", "status": "exists" },
    { "name": "body_records", "status": "created" },
    ...
  ]
}
```

`status` 为 `created`（新建）或 `exists`（已存在）都算成功。

---

## 设置集合权限（必做，API 无法自动设置）

云函数用管理员权限创建集合后，**权限默认为「仅管理端可读写」**，前端读不到数据。需要逐个改：

云开发控制台 → **数据库** → 选择集合 → **权限设置** → 选「**仅创建者可读写**」

> 6 个集合都要设为「仅创建者可读写」。
> 这个权限模式按 `_openid` 判定，用户只能读写自己创建的数据。
> ⚠️ 云函数写入时必须显式带 `_openid` 字段，否则前端读不到（项目代码已处理）。

---

## 建索引（建议，数据量上去后再做）

云开发控制台 → 数据库 → 集合 → 索引管理，建议添加：

| 集合 | 索引字段 | 类型 | 说明 |
|---|---|---|---|
| `workout_logs` | `openid` + `date` | 复合，非唯一 | 打卡范围查询 |
| `body_records` | `openid` + `date` | 复合，非唯一 | 身体记录按日查询 |
| `plans` | `openid` + `status` | 复合，非唯一 | 查当前生效计划 |
| `chat_messages` | `openid` + `createdAt` | 复合，非唯一 | 对话历史倒序 |

数据量小的时候不加也能跑，但超过几百条后查询会变慢。

## 排查「加载失败」

页面现在会显示具体原因，对号入座：

| 页面提示 | 原因 | 解决 |
|---|---|---|
| 数据库集合未创建，请执行 initDb | 集合缺失（-502005） | 按上面「一键初始化」执行 |
| 数据库权限不足 | 权限没设为「仅创建者可读写」（-502003） | 按上面「设置集合权限」改 |
| 云开发环境未就绪 | `app.js` 的 `ENV_ID` 不对 | 云开发控制台 → 设置 → 环境 ID，复制到 `app.js` |
| 登录状态未就绪 | openid 还没拿到 | 稍后重试；持续如此查 `login` 云函数是否部署 |
| 网络异常 | 网络问题 | 检查网络后下拉刷新 |

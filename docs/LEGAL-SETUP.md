**协议升级流程**：改 `content/legal.js` 里的 `LEGAL_VERSION`（如 `v1.0` → `v1.1`）并同步 `UPDATED_DATE`
→ 所有用户下次打开时 `needsReaccept()` 变 true，我的页入口会显示「协议已更新」
→ 建档页重新要求勾选。**只改正文不改版本号，老用户不会被重新征得同意**，这点务必注意。

## 二、平台侧要做的 3 件事

### ① 确认服务类目

公众平台 → 设置 → 基本设置 → 服务类目。
健身记录/训练指导类通常归在「**健康-健康管理**」或「**体育-体育培训/运动健身**」下。
类目决定订阅消息模板的可用范围，**类目不对 → 训练提醒功能整条链路不可用**。

### ② 填写《小程序用户隐私保护指引》（必做）

**改的位置（点击路径）**：[微信公众平台](https://mp.weixin.qq.com) 扫码登录 → 左侧菜单 **「设置」** → **「服务内容声明」** → **「用户隐私保护指引」** → 点右上角 **「修改」**。

> 不同时期平台菜单名略有差异，找不到时：① 在左侧菜单直接看「设置」下是否有「服务内容声明」；
> ② 用后台顶部搜索框搜「隐私」；③ 或试「设置 → 基本设置 → 用户隐私保护指引」。
> 若「修改」按钮是灰的，说明有一版指引正在审核中，需等出结果后再改。

**改什么**：在「收集的信息类型」列表里，**取消勾选 AI 对话 / 深度合成相关的收集项**（V1.0.1 被驳回的根因），
其余按下面表格逐条勾选/填写用途。

**改完的流程**：提交后指引**单独走一次平台审核**（与小程序版本审核是两条独立流程，通常几小时到 1 天）
→ 审核通过后再提交小程序 1.0.2 审核，否则提审时会被判「指引与实际功能不符」。

这份指引**必须与 `content/legal.js` 的 `DATA_ITEMS` 一一对应**，两边对不上是驳回的常见原因。
按下表逐条勾选/填写：

| 收集项 | 平台里对应声明 | 用途（可直接照抄） | 必需 |
|---|---|---|---|
| 微信标识（OpenID） | 用户信息 → 微信授权登录标识 | 识别账号，关联训练数据 | ✅ |
| 身体档案 | 用户信息 → 健康信息（性别/年龄/身高/体重等） | 计算训练强度、生成个性化计划 | ✅ |
| 训练记录 | 用户信息 → 运动数据 | 生成数据看板与打卡统计 | ✅ |
| 身体记录 | 用户信息 → 健康信息（体重/体脂） | 记录身体变化趋势 | ⬜ |
| 头像与昵称 | 用户信息 → 头像、昵称 | 仅「我的」页展示，本人可见 | ⬜ |
| 订阅消息授权 | 用户信息 → 消息订阅 | 发送训练提醒 | ⬜ |
| 本地设置数据 | **不用声明**（仅存本机，未上传） | — | — |

> ⚠️ **2026-10-08 更新**：V1.0.1 提审因「深度合成技术（AI 问答）」被驳回，
> AI 对话功能已整体移除，**「AI 教练对话内容」一项不要再勾选**（收集清单由 8 项降为 7 项）。
> 后台共 **6 项** 需要声明（代码里第 7 项「本地设置数据」仅存本机、不上传，平台无需填写）。
> 整改细节见 [`docs/REVIEW-AI-REMOVAL.md`](./REVIEW-AI-REMOVAL.md)，正文口径已同步至协议 v1.1。

> 若平台要求填写**第三方 SDK**：本小程序只用到「微信云开发」，无其他第三方 SDK，照实填写即可。

### ③ 提交审核时的备注

版本管理 → 提交审核 → 审核备注里建议写明（能显著降低沟通成本）：

```
本小程序为个人健身训练记录工具，不涉及社区、UGC 内容与付费。
用户协议与隐私政策入口位于「我的」页「关于」分组，建档流程中有明确的勾选同意步骤。
未收集手机号、位置、通讯录、相册、剪贴板等信息；身体数据仅本人可见。
```

## 三、一个需要知道的技术决定：为什么没开 `__usePrivacyCheck__`

小程序里有两套「隐私」机制，容易混：

| 机制 | 是什么 | 本项目的处理 |
|---|---|---|
| **平台隐私保护指引** | 后台填写的声明，用户被采集信息时的授权凭证 | ✅ 必做（见上②） |
| **`__usePrivacyCheck__`** | `app.json` 开关，开启后**由开发者自己**接管隐私弹窗 | ❌ **未开启** |

**不开启的原因**：开启后必须自行实现 `wx.onNeedPrivacyAuthorization` + 自定义弹窗组件，
任何一处没接对，`chooseAvatar`（头像选择）就会直接失败——而这正是本项目唯一用到的隐私接口。
不开启时，平台会用自己的弹窗完成授权，链路更稳。

**代价**：授权弹窗是平台样式，与小程序 UI 不统一。
**如果日后要自控**（比如想统一视觉），改动点为：
1. `app.json` 加 `"__usePrivacyCheck__": true`
2. `app.js` 里注册 `wx.onNeedPrivacyAuthorization`，弹出自定义隐私弹窗组件
3. 弹窗「同意」按钮调用 `resolve({ event: 'agree' })`

## 四、提审前自检

- [ ] 后台《用户隐私保护指引》已提交并通过审核
- [ ] 指引中的收集项与 `content/legal.js` 的 `DATA_ITEMS` 一致（代码 7 项，其中 3 项必需；后台声明 6 项）
- [ ] 真机验证：建档 → 不勾选协议点「完成建档」→ 被拦下 + 抖动 + toast
- [ ] 真机验证：勾选 → 能正常建档
- [ ] 真机验证：我的页 → 用户协议 / 隐私政策 都能打开，正文完整、版本与生效日期可见
- [ ] 真机验证：协议页顶部标签可切换两份文档
- [ ] 开发者工具里确认协议页无 `rpx` 溢出错位（正文段落行高 1.8，长段落应正常换行）
- [ ] 联系邮箱：`content/legal.js` 的 `CONTACT` 目前填的是 GitHub 地址。
      若希望提供邮箱（部分审核员会要求可联系的邮箱），改这一个常量即可，两份文档会同步生效
